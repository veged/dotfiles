# Create Slidev Theme

## Результат

Создать тему Slidev с токенами, публичными макетами, документацией и проверками. При работе по шаблону отдельно сохранить точную контрольную презентацию источника.

## Режимы

* **Описание** — вывести систему из задачи, аудитории, тона и ограничений фирменного стиля
* **Шаблон** — извлечь структуру PPTX или Keynote и доказать полноту воспроизведения
* **Смешанный** — взять геометрию из шаблона, намерение из описания, фирменный стиль из руководства по оформлению
* **Обновление** — сохранить публичный интерфейс темы либо описать миграцию

## Инварианты

1. Не изменять оригиналы. Хешировать исходники и производные экспорты.
2. Учитывать каждый слайд. Исключения хранить с причиной.
3. Разделять контрольную презентацию и публичную дизайн-систему.
4. Не исправлять источник молча. Описывать каждую нормализацию как точную операцию.
5. Не принимать общий процент различий за доказательство геометрии.
6. Не завершать работу без полного восстановления конвейера из чистой копии репозитория.

## Процесс

### 1. Зафиксировать контракт

Записать назначение, аудиторию, формат, обязательные элементы, лицензии, среду выполнения и критерии приёмки. Не спрашивать то, что можно надёжно извлечь из файлов.

### 2. Инвентаризировать и извлечь источник

Прочитать [маршрутизацию входов](references/input-routing.md) и [модель извлечения](references/source-extraction.md). Скопировать оригинал без изменений в `reference/sources/`: так манифесты содержат переносимые пути, а чистая копия репозитория может проверить реальные хеши.

```bash
node scripts/inventory-inputs.mjs --root {каталог-темы} \
  --output reference/source-inputs.json reference/sources/{шаблон.pptx}
python3 scripts/inspect-pptx.py reference/sources/{шаблон.pptx} \
  --input-id reference/sources/{шаблон.pptx} \
  --output reference/source-structure.json \
  --loss-output reference/source-losses.json \
  --media-dir reference/source-media
```

Для Keynote сначала получить проверяемые экспорты:

```bash
python3 scripts/export-keynote.py reference/sources/{шаблон.key} \
  --source-id reference/sources/{шаблон.key} \
  --output-dir reference/keynote-export
```

Экспорт Keynote считается годным только после совпадения четырёх количеств и попарного сравнения изображений с растром PDF. Считать визуализацию источником внешнего вида, а структурный экспорт — источником редактируемых свойств. При расхождении порядка или числа слайдов остановиться и построить явную карту соответствий.

### 3. Построить контрольную модель

Создать:

* `source-structure.json` — структура пакета и объектов
* `source-losses.json` — неподдержанные или неоднозначные свойства
* `source-map.json` — взаимно однозначное отображение источника на контрольную презентацию и исключения
* `source-normalizations.json` — разрешённые системные исправления
* `render-environment.json` — версии средств, размеры, DPR, шрифты и цветовой профиль

Контрольную презентацию строить из карты, а не из зашитого диапазона номеров. Сложный объект разрешено заменить растровым фрагментом только с точной областью, происхождением и записью о потере структуры.

### 4. Вывести дизайн-систему

Прочитать [контракт дизайн-системы](references/design-system.md). Объединить повторения в небольшое семейство макетов по задаче в рассказе. Не создавать макет на каждый исходный слайд.

### 5. Реализовать тему

Прочитать [контракт реализации Slidev](references/slidev-implementation.md). Сделать основной авторский путь простым: Markdown, именованные области, поле `layout` и несколько семантических параметров. Контрольную часть и исходные материалы исключить из пакета npm.

### 6. Доказать точность и устойчивость

Прочитать [контракт визуальной проверки](references/visual-fidelity.md). Создать одну воспроизводимую цепочку:

```text
экспорт → разбор → карта → контрольная презентация → визуализация → сравнение → проверка → привязка
```

Разделить команды:

* `fidelity:verify` заново строит изображения и пересчитывает метрики
* `fidelity:provenance` проверяет привязку сохранённого отчёта к входам и среде
* `check:consumer` устанавливает упакованную тему во внешний пример и визуализирует его

Проверить контракт:

```bash
node scripts/check-theme-contract.mjs {каталог-темы}
node scripts/check-theme-contract.mjs --template-mode {каталог-темы}
```

Эта команда проверяет структуру и хеши контракта. Полноценный `npm test` обязан реально выполнить команды построения, визуализации и сравнения; наличие их имён не считается доказательством запуска.

### 7. Передать результат

Оставить `README.md`, полную галерею `example.md`, контактный лист, инструкцию для автора и одну команду всех проверок.

## Критерии приёмки

* все исходные слайды отображены или явно исключены
* структура, потери, нормализации и среда записаны машинно
* публичные макеты покрыты галереей и эталонными изображениями
* глобальный сдвиг равен `[0, 0]`, кроме объявленных локальных операций
* проверены локальная геометрия, переполнения, наложения и ошибки браузера
* эталоны нельзя обновить при непройденных метриках
* чистая копия репозитория восстанавливает артефакты повторно и идемпотентно
* исходники, контрольная презентация и отчёты не попадают в пакет npm
