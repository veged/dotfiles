# Реализация Slidev

## Структура пакета

Минимальная структура темы:

```text
components/  composables/  layouts/  setup/  styles/
tokens/      types/        scripts/  tests/  skills/
example.md   README.md     package.json
```

В `package.json` задать `slidev.defaults.canvasWidth`, `aspectRatio`, `fonts.provider` и явный разрешённый список `files`. Имя пакета — `slidev-theme-*` или вариант с областью видимости.

## Разделить части

Публичный пакет содержит стабильные макеты, компоненты, токены, стили, оптимизированные ресурсы и инструкцию для автора.

Каталог `reference/`, исходные PPTX/Keynote, контрольная презентация, отчёты и тяжёлые изображения остаются внутренними. Проверить фактический состав через `npm pack --dry-run`, а затем установить архив во внешний пример.

## Сделать авторский интерфейс

Основной путь использует Markdown, именованные области и компактные метаданные:

```markdown
---
layout: metrics
variant: accent
columns: 3
---

# Результаты квартала
```

Не требовать ручных координат. Отделять свойства содержимого от оформления. Документировать редкий способ точечной настройки.

Не использовать поле Slidev `image` для внутренних псевдонимов ресурсов: Slidev может обработать его как путь до преобразователя темы и вызвать ошибку 404. Использовать семантические поля `media`, `media2` и подобные либо проверенный компонент.

## Подготовить ресурсы

* сохранять SVG для векторной графики
* оптимизировать крупные растры без потери нужной детализации
* хранить исходную связь медиа с кадрированием отдельно от публичного файла
* фиксировать запасные гарнитуры и не зависеть от скрытой загрузки сети
* не встраивать коммерческие шрифты без разрешения

## Проверять презентацию

Средство проверки должно находить до визуализации:

* неизвестный макет или вариант
* отсутствующую именованную область
* несовместимые параметры
* превышение числа карточек или колонок
* отсутствующий ресурс
* превышение ёмкости содержимого

Сообщение содержит номер слайда, причину и конкретное исправление.

## Сделать галерею спецификацией

Файл `example.md` покрывает каждый публичный макет и важный вариант. Добавить длинный русский заголовок, плотные данные, код в 1–3 колонки и крайние допустимые объёмы.

Файл `README.md` объясняет установку, выбор макета, метаданные, именованные области, ограничения, ресурсы, код, русскую типографику и команды проверки.

Сгенерировать единый контактный лист. Встроенная инструкция для автора должна помогать выбирать макет и запускать проверку, а не дублировать `README.md`.

## Собрать проверки

Единая команда `test` должна включать:

```text
tokens:check
test:unit
validate
check:architecture
typecheck
build
check:render
check:pixels
check:package-assets
check:consumer
```

Для режима шаблона добавить `source:inspect`, `source:build`, `source:render`, `fidelity:verify` и `fidelity:provenance`.

`check:render` проверяет каждый слайд, ошибки браузера, переполнения и наложения. `check:pixels` сравнивает галерею с принятыми эталонами. `check:consumer` повторяет сборку после установки упакованной темы в отдельный проект.
