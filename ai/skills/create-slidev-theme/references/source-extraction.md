# Извлечение PPTX и Keynote

## Обязательные артефакты

* `source-inputs.json` — хеши оригиналов и экспортов
* `source-structure.json` — версия схемы, части пакета, связи, слайды и объекты
* `source-losses.json` — неподдержанные, неоднозначные и растеризованные свойства
* `source-map.json` — каждый исходный слайд, контрольный слайд или исключение
* `render-environment.json` — движок, версия, область просмотра, DPR, шрифты и профиль цвета

## Разбор OOXML

1. Прочитать `[Content_Types].xml` и полный список частей пакета.
2. Разрешить все `.rels`; сохранить внешние и сломанные цели.
3. Получить размер `p:sldSz`, порядок, устойчивые идентификаторы, разделы и скрытые слайды.
4. Для каждого слайда пройти цепочку `slide → layout → master → theme`.
5. Сохранить заполнители и локальные переопределения, не теряя происхождение.
6. Обойти дерево фигур в порядке слоёв, включая вложенные `p:grpSp`.
7. Извлечь фигуры, изображения, соединители, таблицы, графики, SmartArt, OLE, заметки и комментарии.
8. Сохранить текстовые фрагменты, свойства абзацев, интервалы, поля текстовой области и гиперссылки.
9. Для медиа записать MIME-тип, SHA-256, связь, встроенность, место использования и данные кадрирования.
10. Собрать гарнитуры темы и текста, встроенные шрифты и неизвестные лицензии.

Не выдавать сохранённые слои за вычисленный итоговый стиль. Если извлекатель не материализует каскад `slide → layout → master → theme`, записать структурную потерю и проверить результат эталонным рендером. Неизвестные XML-свойства сохранять как дерево с пространствами имён и атрибутами.

## Keynote

Работать только с копией `.key`. Одним запуском Keynote экспортировать PPTX, PDF и изображения. Обязательны четыре независимых количества: слайды документа, PPTX, страницы PDF и изображения. Неизвестное число страниц PDF — ошибка, а не пропуск проверки.

Порядок изображений получать из числового индекса в имени, а не из лексикографической сортировки. Индексы должны образовывать последовательность `1..N`. Для каждого индекса сравнить изображение Keynote с той же страницей PDF после одинаковой растеризации; сохранить метрику и порог в манифесте.

HTML-экспорт Keynote полезен как дополнительный источник порядка, размеров и доступного текста: `assets/header.json` описывает документ, а `assets/<slide>/<slide>.json` — события и прямоугольники. Он не заменяет PDF и изображения как визуальную истину.

## Координаты

Сохранять исходные значения в EMU. Нормализовать их по `p:sldSz`, а не по постоянному коэффициенту. Например, коэффициент `6350` верен только для преобразования ширины `12192000 EMU` в `1920 px`.

Для группы композиционно применять `off/ext/chOff/chExt`, затем поворот и отражения. Для изображения согласованно применять матрицу группы, собственный поворот, маску и `a:srcRect`. Округлять только на границе визуализации.

Хранить локальную матрицу и матрицу до координат слайда. Если геометрию нельзя воспроизвести, записать потерю; не заменять её прямоугольником молча.

## Сложные объекты

Для графика извлечь XML графика, ряды, оси, кэши и встроенную книгу. Для таблицы — сетку, ячейки, объединения и стили. Для SmartArt и OLE сохранить части, связи и растровый запасной вариант.

Растровая замена допустима в контрольной презентации, если запись содержит:

* часть OOXML, идентификатор фигуры и номер слайда
* точную область и хеш изображения
* причину потери структуры
* ожидаемую геометрию

## Карта слайдов

`source-map.json` должен быть самодостаточным:

```json
{
  "version": 1,
  "sourceSlides": 2,
  "mappings": [
    { "sourceSlide": 1, "fixtureSlide": 1 }
  ],
  "exclusions": [
    { "sourceSlide": 2, "reason": "Служебный слайд", "approved": true }
  ]
}
```

Каждый исходный номер встречается ровно один раз. Номера контрольных слайдов не повторяются. Число отображений и исключений равно числу слайдов структуры.

## Происхождение и потери

Каждый элемент контрольной презентации должен ссылаться на часть OOXML, связь и идентификатор исходной фигуры. `source-losses.json` группирует потери по уровню:

* `fatal` — нельзя доказать полноту или порядок
* `structural` — внешний вид сохранён, редактируемая структура потеряна
* `visual` — ожидается заметное отличие
* `informational` — свойство не влияет на статичный слайд

Не продолжать при `fatal`. Остальные потери показать в отчёте и покрыть локальным сравнением.

## Проверка извлекателя

Добавить синтетический PPTX и эталонный JSON со следующими случаями: наследование макета, переопределение заполнителя, вложенная группа, поворот, отражение, кадрирование, связанные и встроенные медиа, гарнитура текста, график с книгой, объединённая таблица, заметки и скрытый слайд.

В чистой копии репозитория удалить производные файлы, восстановить их и повторить запуск. Второй запуск должен дать те же хеши, кроме заранее описанных различий движка.
