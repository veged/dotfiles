# Маршрутизация входов

## Общий порядок

1. Сохранить оригинал без изменений.
2. Хешировать оригинал и каждый экспорт.
3. Получить независимые представления структуры, текста и внешнего вида.
4. Сверить число, порядок и размеры слайдов.
5. Описать доверие к каждому представлению до реализации темы.

Не выбирать один «главный» файл для всех свойств. Экспорты теряют разные данные.

## Только описание

Извлечь задачу, аудиторию, дистанцию просмотра, типы содержимого, язык, плотность, долю медиа и ограничения фирменного стиля. Сначала сделать 4–6 проверочных композиций: обложку, раздел, текст, данные, медиа и финал. После согласования ритма реализовать остальные макеты.

## PPTX

PPTX — ZIP-пакет OOXML. Обязательно разобрать `presentation.xml`, слайды, связи `.rels`, макеты, мастер-слайды, тему, медиа, заметки и встроенные документы. Чтения только `slides/*.xml` недостаточно: геометрия и стили часто наследуются.

Запустить `inspect-pptx.py` и проверить отчёт о потерях. Не извлекать только `ppt/media`: без связи с местом использования теряются порядок слоёв, кадрирование, поворот, группа, гиперссылка и описание для средств доступности.

Визуализировать все слайды тем же движком, который определяет ожидаемый вид. Записать его название и версию.

## Keynote

На macOS открыть только рабочую копию `.key`. `export-keynote.py` должен получить PPTX, PDF и изображения отдельных слайдов, записать версии Keynote/macOS и построить карту:

```text
слайд Keynote → слайд PPTX → страница PDF → PNG
```

Остановиться при расхождении числа или порядка. В реальных экспортах HTML и PPTX число слайдов может различаться из-за сборок и состояний.

Если доступен HTML-экспорт Keynote, брать полноту и порядок из `assets/header.json`, а текст и прямоугольники — из `assets/{slide}/{slide}.json`. PPTX использовать для нормализованных свойств, PDF — для текста, PNG — для внешнего вида.

Прямой разбор IWA считать дополнительным источником. Средство разбора может завершиться ошибкой на неизвестном типе Protocol Buffers; в таком случае читать только нужные IWA-записи, а не декодировать весь архив. Числа из IWA нельзя принимать без визуальной калибровки.

Если Keynote недоступен, запросить PPTX, PDF и PNG. Не заявлять структурную точность по предпросмотру Quick Look.

## PDF и изображения

PDF уточняет видимый текст и координаты, но не заменяет структуру:

```bash
pdftohtml -xml -zoom 1 -stdout -f 1 -l 1 {слайды.pdf}
pdftotext -layout {слайды.pdf} -
```

Параметр `-zoom 1` обязателен: без него координаты могут получить лишний масштаб. Проверить, не содержит ли PDF несколько страниц-состояний одного слайда.

Изображения использовать как визуальную истину и источник локальных фрагментов. Не превращать публичный макет в один скриншот.

## Матрица доверия

* **Полнота и порядок** — экспорт из исходного приложения или HTML-манифест Keynote
* **Структура** — OOXML с учётом наследования и связей
* **Текст** — OOXML, затем PDF как проверка переносов и маркеров
* **Внешний вид** — PNG/PDF из исходного редактора
* **Медиа** — оригинальные файлы плюс данные места использования

При конфликте записать решение в `template-audit.md`, а не выбирать источник молча.
