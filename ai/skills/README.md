# Навыки

Общий слой навыков в `ai/skills/`. Рабочие каталоги и общая архитектура — в [`../README.md`](../README.md).

## Структура

В `ai/skills/` смешиваются два источника:

* локальные skill-пакеты — подкаталоги с `SKILL.md` (имя = имя каталога)
* внешние зависимости — реестр в `ai/skills/skills.json`

```text
ai/skills/
├── editorial/
│   └── SKILL.md
├── prompt/
│   └── SKILL.md
├── skills.json
└── README.md
```

## Формат `skills.json`

Словарь `source → spec`.

`source`:

* `owner/repo#<full-commit-sha>`
* `owner/repo#<full-commit-sha>:path/to/subdirectory`
* полный Git URL с тем же суффиксом `#<sha>[:path]`
* git-URL (`*.git`, `ssh://...`, `git://...`) — навык ищется по имени в корне репозитория, `skills/` или `.claude/skills/`
* явный локальный путь: `~/...`, `/...`, `./...` или `../...`

Удалённые источники канонического реестра должны быть закреплены полным SHA.
Форма без SHA поддерживается как legacy-ввод, который `/dotfiles:install`
нормализует перед записью.

`spec`:

* `"*"` — установить весь источник
* `"skill-name"` — установить один навык
* `["skill-a", "skill-b"]` — установить список
* `"!skill-name"` или `["!skill-a", "!skill-b"]` — установить весь источник, кроме перечисленных навыков

В одном списке нельзя смешивать включения и исключения: `["skill-a", "!skill-b"]` считается ошибкой.

## Правила сборки

* `./scripts/install-skills` собирает локальные пакеты и внешние зависимости в `~/.agents/skills`, затем запускает projection в assistant-specific слои (`~/.claude/skills`, `~/.codex/skills`, `~/.cursor/skills`)
* локальный skill-пакет, подключённый в `ai/skills/` symlink-ом, сохраняется symlink-ом в `~/.agents/skills`
* старые прямые ссылки на зарегистрированные локальные источники заменяются каноническими, только если совпадает весь пакет; старый псевдоним каталога убирается, разные версии и ручные переопределения сохраняются
* для разработки внешнего skill можно вручную заменить его каталог в `~/.agents/skills/<name>` symlink-ом на рабочую копию — `install-skills` уважает такой override и не перетирает его
* конфликт имени между локальным и внешним skill — жёсткая ошибка
* конфликт имён между внешними источниками — жёсткая ошибка
* источник с commands, manifests или общими ресурсами регистрируется целиком в `plugins.json`, а не разрезается на отдельные skills
* `./scripts/bootstrap-agent-skills` при необходимости мигрирует `codex-primary-runtime` из `~/.codex/skills` в канонический слой, обычно вызывается из `install-skills`

## Установка

```bash
./scripts/install-skills
./scripts/install-skills --update
```

`--update` переустанавливает внешние зависимости. Локальные пакеты синхронизируются при каждом запуске. `--force` оставлен алиасом.

## Каталог подробных процедур

Два локальных входных навыка выбирают нужную инструкцию из установленных наборов:

- [`mblode`](mblode/SKILL.md) — 24 процедуры разработки, дизайна, документации и выпусков.
- [`course-workflow`](course-workflow/SKILL.md) — 23 этапа производства курсов и выбор существующего оркестратора.

Подробные процедуры сохранены на месте вместе с ресурсами. Список в [`discovery.json`](discovery.json) задаёт для них `policy.allow_implicit_invocation: false` в `agents/openai.yaml`: Codex оставляет явный вызов по имени, а начальный каталог содержит входные навыки. Вход читает выбранную исходную инструкцию и её ресурсы по месту хранения.

`install-skills` и `install-plugins` запускают `scripts/sync-skill-discovery`, который применяет политику к установленным навыкам, исходным пакетам и существующим версиям кэша Codex. Остальные поля метаданных сохраняются. После обновления плагина напрямую в клиенте повтори `./scripts/sync-skill-discovery`, проверить состояние можно с `--check`. Входные навыки устанавливаются обычным `install-skills --local-only`. Уже запущенное приложение может держать каталог плагинов в памяти: после применения политики и изменения конфигурации перезапусти Codex и проверь новый начальный контекст.

Бюджет метаданных каталога — `skills.max_context_tokens = 3500`. Это внутренняя приблизительная оценка Codex, не точное число токенов всей секции навыков. После изменения набора проверяй фактический каталог: все входы и несвязанные навыки должны оставаться видимыми, описания могут сокращаться. Эта настройка не ограничивает чтение выбранных инструкций. Проверяй, что пути в таблицах существуют и ссылаются на исходные пакеты, не копируй инструкции в указатели.
