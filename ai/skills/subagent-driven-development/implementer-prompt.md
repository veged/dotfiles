# Шаблон исполнителя для Work Unit

Шаблон описывает один независимо принимаемый рабочий блок. Его задачи
передаются отдельными файлами.

```yaml
description: "Реализовать Work Unit N: {название}"
fork_turns: "none"
model: "[MODEL — выбрать по SKILL.md]"
message: |
  Реализуй Work Unit N: {название}.

  ## Требования

  Прочитай файлы:

  [BRIEF_FILES]

  Вместе они задают один рабочий блок. Не читай полный план и историю
  сессии.

  Контекст: {место блока в проекте}
  Интерфейсы и принятые решения: [INTERFACES]
  Рабочая директория: [WORKDIR]

  Если требования или зависимости неоднозначны, верни NEEDS_CONTEXT и задай
  конкретный вопрос. Не принимай архитектурных решений наугад.

  ## Работа

  1. Реализуй только требования переданных файлов
  2. Следуй TDD, если этого требует план или навык задачи
  3. Во время работы запускай узкие тесты, полный набор — один раз перед
     фиксацией в Git
  4. Зафиксируй результат в Git
  5. Проверь полноту, качество, YAGNI и ценность тестов

  Не рефактори соседний код без необходимости. Если блок требует более
  широкого архитектурного решения, верни BLOCKED или DONE_WITH_CONCERNS.

  ## Исправления

  Получив замечания, исправь их одним пакетом. Повтори нужные тесты и дополни
  прежний отчёт: изменение, тестовые файлы, команда и существенный результат.

  ## Отчёт

  Запиши в [REPORT_FILE]:

  - выполненные требования
  - фиксации Git и изменённые файлы
  - команды тестов и результаты
  - доказательства RED/GREEN, если требовался TDD
  - результат самопроверки
  - сомнения или препятствия

  Добавь раздел `Excluded-content validation`:

  - перечисли изменённые файлы блокировки зависимостей
  - для каждого укажи команду проверки, результат и полный `HEAD`
  - если таких файлов нет, напиши `lock-files: none`

  Не возвращай DONE без актуальной проверки изменённого файла блокировки.

  Финальный ответ — не более 15 строк:

  - Status: DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
  - фиксации Git
  - результат тестов
  - сомнения
  - путь к отчёту

  Для BLOCKED и NEEDS_CONTEXT продублируй причину в ответе.
```

## Поля шаблона

* `[MODEL]` — выбранная модель
* `[BRIEF_FILES]` — файлы задач рабочего блока
* `[INTERFACES]` — нужные интерфейсы и решения
* `[WORKDIR]` — путь к изолированному `worktree`
* `[REPORT_FILE]` — отчёт рабочего блока
