# Шаблон исполнителя

```yaml
description: "Реализовать рабочий блок {номер}: {название}"
fork_turns: "none"
model: "{модель}"
message: |
  Реализуй рабочий блок {номер}: {название}.

  Прочитай только эти задания:

  {файлы_заданий}

  Контекст проекта: {контекст_проекта}
  Интерфейсы и принятые решения: {интерфейсы}
  Рабочий каталог: {рабочий_каталог}
  Граница одного хода: {граница_хода}
  Политика делегирования: {политика_делегирования}
  Отчёт: {файл_отчёта}

  Без явного разрешения выполняй блок сам. Не запускай дочерних агентов
  и навыки, которые создают новое дерево. Если выгодно выделить минимум два
  независимых подблока, верни статус НУЖЕН_КОНТЕКСТ с картой и оценкой ходов.

  При неоднозначности требований верни статус НУЖЕН_КОНТЕКСТ и задай
  конкретный вопрос. Не принимай архитектурных решений наугад.

  1. Реализуй только переданные требования
  2. Следуй TDD, если этого требует задание
  3. Во время работы запускай узкие тесты
  4. Перед фиксацией выполни один уместный полный набор тестов
  5. Зафиксируй результат в Git
  6. Проверь полноту, лишний объём и ценность тестов

  Не рефактори соседний код без необходимости. Если блок требует расширить
  архитектурные границы, верни ЗАБЛОКИРОВАНО или ГОТОВО_С_ОГОВОРКАМИ.

  Получив замечания, исправь их одним пакетом, повтори нужные тесты
  и дополни прежний отчёт.

  В отчёте укажи:

  - выполненные требования
  - фиксации Git и изменённые файлы
  - команды тестов и результаты
  - доказательства красной и зелёной стадий, если требовался TDD
  - результат самопроверки
  - сомнения и препятствия

  Добавь раздел «Проверка исключённого содержимого». Для каждого изменённого
  файла блокировки зависимостей укажи команду, результат и проверенную версию.
  Если таких файлов нет, напиши: «Файлы блокировки: нет».

  Не отправляй промежуточные статусы без запроса. Вернись раньше финала только
  при препятствии, нехватке контекста или предусмотренной контрольной точке.

  Финальный ответ не должен превышать 15 строк:

  - статус: ГОТОВО | ГОТОВО_С_ОГОВОРКАМИ | ЗАБЛОКИРОВАНО | НУЖЕН_КОНТЕКСТ
  - фиксации Git
  - результат тестов
  - сомнения
  - путь к отчёту
```

## Поля

* `{номер}` — номер рабочего блока
* `{название}` — короткое название блока
* `{модель}` — выбранная модель
* `{файлы_заданий}` — пути к заданиям
* `{контекст_проекта}` — место блока в проекте
* `{интерфейсы}` — нужные интерфейсы и решения
* `{рабочий_каталог}` — путь к изолированному рабочему дереву
* `{граница_хода}` — допустимый объём одного хода
* `{политика_делегирования}` — разрешение и бюджет либо явный запрет
* `{файл_отчёта}` — путь к отчёту блока
