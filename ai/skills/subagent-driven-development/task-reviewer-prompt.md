# Шаблон проверяющего высокорискового блока

```yaml
description: "Проверить рабочий блок {номер}"
fork_turns: "none"
model: "{модель}"
message: |
  Проверь высокорисковый рабочий блок {номер}.

  Задания: {файлы_заданий}
  Обязательные требования: {обязательные_требования}
  Отчёт исполнителя: {файл_отчёта}
  Исходная версия: {исходная_версия}
  Проверяемая версия: {проверяемая_версия}
  Пакет изменений: {файл_пакета}
  Политика делегирования: {политика_делегирования}

  Без явного разрешения проводи ревью сам. Не запускай дочерних агентов
  и дополнительные оси проверки.

  Считай отчёт заявлениями, а не доказательством. Пакет и проверяемая версия
  образуют неизменяемый снимок. При расхождении верни
  УСТАРЕВШИЙ_СНИМОК и остановись.

  Прочитай пакет один раз. Не обходи репозиторий целиком и не меняй рабочее
  дерево, индекс Git, версию или ветку.

  Не повторяй подтверждённые тесты. Узкий тест допустим только для конкретного
  сомнения без ответа в отчёте.

  Сначала сопоставь изменения со всеми требованиями:

  - требование пропущено
  - добавлен неподтверждённый объём
  - реализована неверная семантика
  - пакет не позволяет провести проверку

  Затем оцени корректность, обработку ошибок, границы ответственности,
  соответствие проекту и ценность тестов.

  Уровни замечаний:

  - критическое
  - важное
  - незначительное

  Для каждого замечания укажи {путь}:{строка}, риск и направление исправления.

  Не отправляй промежуточные статусы без запроса. Вернись раньше финала только
  при устаревшем снимке, препятствии или нехватке контекста.

  Начни ответ с замечаний, затем дай вердикт:
  ПРИНЯТО | НУЖНЫ_ИСПРАВЛЕНИЯ | НЕЛЬЗЯ_ПРОВЕРИТЬ | УСТАРЕВШИЙ_СНИМОК.
```

## Поля

* `{номер}` — номер рабочего блока
* `{модель}` — выбранная модель
* `{файлы_заданий}` — пути к заданиям блока
* `{обязательные_требования}` — применимые требования
* `{файл_отчёта}` — отчёт исполнителя
* `{исходная_версия}` — начало диапазона
* `{проверяемая_версия}` — конец диапазона
* `{файл_пакета}` — пакет от `scripts/review-package`
* `{политика_делегирования}` — разрешение и бюджет либо явный запрет
