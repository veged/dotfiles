# Адаптивная разработка с агентами

Соблюдай действующую политику оркестрации проекта. Этот навык определяет только
процесс исполнения нескольких независимых блоков.

Рабочий блок — минимальное изменение, которое можно отдельно реализовать,
проверить и отклонить.

## Применимость

Сначала сгруппируй задачи плана.

Объединяй задачи, если они меняют один артефакт, зависят от точной формы
предыдущего результата или описывают последовательные стадии одной работы.

Сохраняй границу, только если один блок можно отклонить, не отклоняя соседний.
Для этого навыка нужны минимум два независимых блока. Один связный блок
передавай `executing-plans` или одному исполнителю.

## Подготовка

Для каждого блока запиши:

* задачи и проверяемый результат
* зависимости
* обычный или высокий риск
* обязательные тесты
* необходимость подтверждения пользователя

Высокий риск назначай изменениям безопасности, данных, публичных контрактов,
конкурентности, распределённого состояния и архитектуры нескольких подсистем.
Размер изменения сам по себе не повышает риск.

Составь общий бюджет по действующей политике оркестрации. Включи в него
исполнителей, проверяющих, исправления и заранее разрешённые дочерние ходы.

Создай изолированное рабочее дерево. Получи каталог журналов и пакетов:

```bash
scripts/sdd-workspace {путь_к_плану}
```

Для каждой задачи при необходимости создай краткое задание:

```bash
scripts/task-brief {путь_к_плану} {номер_задачи}
```

Если вызывающий навык уже передал готовые задания, используй их и не извлекай
повторно.

## Неизменяемый снимок

Перед ревью зафиксируй исходную и проверяемую версии. Пока проверяющий работает,
не меняй проверяемые файлы.

Если версия изменилась, пометь пакет и результат устаревшими. После завершения
изменений создай один новый пакет. Не запускай замену проверяющего
для движущейся цели.

## Исполнение блока

Не запускай нескольких исполнителей в одном рабочем дереве.

1. Передай исполнителю краткие задания, нужные интерфейсы, границы и путь
   к отчёту
2. Используй [шаблон исполнителя](implementer-prompt.md)
3. Проверь фиксации, тесты и самопроверку в отчёте
4. Для высокого риска создай пакет и запусти независимое ревью
5. Закрой блок или передай один пакет исправлений

Исполнитель возвращает один из четырёх статусов:

* `ГОТОВО`
* `ГОТОВО_С_ОГОВОРКАМИ`
* `НУЖЕН_КОНТЕКСТ`
* `ЗАБЛОКИРОВАНО`

Продолжай того же исполнителя только для конкретного недостающего контекста
или одного пакета исправлений. Не повторяй попытку без изменения условий.

## Ревью блока

Для обычного риска проверь отчёт, самопроверку и доказательства для изменённых
файлов блокировки зависимостей. Запиши, что отдельное ревью не требовалось.

Для высокого риска:

1. Создай пакет

   ```bash
   scripts/review-package {путь_к_плану} {исходная_версия} {проверяемая_версия}
   ```

2. Передай проверяющему задания, отчёт, пакет и обязательные требования

3. Используй [шаблон проверяющего](task-reviewer-prompt.md)

Не повторяй подтверждённые тесты для той же версии. Узкая проверка допустима
только для конкретного сомнения.

## Исправления

Исправляй нарушение требований, критические и важные замечания, а также
подтверждённые пробелы проверки. Незначительные замечания сохраняй
для итогового решения.

Передай исполнителю все замечания одним пакетом. После исправления создай пакет
изменений и запусти свежую узкую перепроверку
по [отдельному шаблону](re-review-prompt.md).

Передавай перепроверяющему только открытые замечания, исправляющий пакет,
актуальный отчёт и необходимые требования.

Обычный предел — один раунд исправлений и одна узкая перепроверка. Второй раунд
допустим только для незакрытого критического или важного замечания
в высокорисковом блоке.

## Пакет ревью

`scripts/review-package` включает фиксации Git, статистику и полные изменения
обычных исходных файлов. Вместо содержимого он записывает манифест для:

* файлов блокировки зависимостей
* двоичных файлов
* минифицированных файлов и карт исходного кода
* сгенерированных каталогов и файлов

Для каждого изменённого файла блокировки отчёт исполнителя должен содержать
раздел «Проверка исключённого содержимого» с командой, результатом и проверенной
версией.

Предел пакета — 200 КиБ. При переполнении сузь рабочий блок или создай несколько
пакетов. Переменная `SDD_REVIEW_PACKAGE_MAX_BYTES` задаёт обоснованное
исключение.

## Подтверждение пользователя

Для субъективных артефактов сначала выполни дешёвые проверки и покажи
предварительный результат. Полный визуальный, браузерный или экспортный
контроль качества запускай после подтверждения пользователя.

Если обратная связь пришла во время ревью:

1. Останови устаревшее ревью
2. Объедини связанные правки в прежний блок
3. Продолжи исходного исполнителя
4. Зафиксируй новую версию
5. После подтверждения проведи один итоговый контроль

Не создавай отдельную цепочку для производного файла, который лишь
синхронизирует тот же артефакт.

## Итоговое ревью

После всех блоков проведи ровно одно итоговое ревью:

1. Создай пакет общего диапазона
2. Передай все требования, отчёты и отложенные замечания
3. Используй [шаблон итогового проверяющего](final-reviewer-prompt.md)
4. Передай критические и важные замечания одному исполнителю
5. После одного пакета исправлений проверь только открытые замечания
   и возможные регрессии

Не запускай второго полного ревью. Оставшийся критический дефект блокирует
завершение.

Если вызывающий навык оставляет за собой завершающую верификацию, сохрани
рабочую область и верни управление после чистого ревью. Очищай рабочую область
только после отдельного разрешения.
