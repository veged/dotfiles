# Ревью изменений

Соблюдай действующую политику оркестрации проекта. Этот навык определяет только
границы и результат ревью.

## Роль

Если запрос уже задаёт снимок, пакет или ось проверки, выполни ревью сам.
Не создавай дополнительное дерево агентов без явного разрешения и бюджета.

Корневой координатор может разделить широкое или высокорисковое ревью на две
независимые оси:

* соответствие требованиям
* инженерное качество и риски

Малый или узкий набор изменений проверяй одним проходом. Не создавай отдельного
агента для объединения результатов.

## Подготовка

Определи:

* исходную и проверяемую версии
* файлы требований и правила репозитория
* изменённые и исключённые из пакета файлы
* уже подтверждённые проверки
* разрешённую ось ревью

Если снимок изменился после запуска, верни вердикт «Устаревший снимок».
Не перечитывай движущуюся цель и не исправляй проверяемые файлы.

Не повторяй тесты, подтверждённые для той же версии. Узкая проверка допустима
только для конкретного сомнения без ответа в отчёте.

## Проверка

Сначала сопоставь изменения со всеми требованиями. Для каждого расхождения
выбери одну причину:

* требование пропущено
* добавлен неподтверждённый объём
* реализована неверная семантика
* пакет не позволяет провести проверку

Затем проверь корректность, обработку ошибок, граничные случаи, безопасность,
совместимость интерфейсов, целостность данных, конкурентность,
производительность затронутого пути и ценность тестов.

Не требуй рефакторинга, который не снижает риск текущего изменения.

## Замечания

Используй три уровня:

* критическое — возможны потеря данных, уязвимость или системный отказ
* важное — изменение нельзя принять без исправления
* незначительное — улучшение не блокирует принятие

Для каждого замечания укажи место, нарушенное требование или сценарий отказа,
практический риск и минимальное направление исправления.

Не включай предположение без воспроизводимого сценария или прямого
несоответствия требованию.

## Ответ

Начни с замечаний по убыванию серьёзности. Затем укажи вердикт, проверенный
диапазон, непроверяемые требования, состояние тестов и остаточные риски.

Если замечаний нет, скажи это прямо. Не описывай процесс ревью.
