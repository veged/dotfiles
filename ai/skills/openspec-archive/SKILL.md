# Архивация OpenSpec

Архивируй изменение только по явному запросу и после слияния. Навык завершает
изменение OpenSpec, но не управляет Git-историей.

## Определение основной ветки

Определи основную ветку только из одного однозначного источника:

1. Сначала прочитай явную конфигурацию проекта
   `git config --get openspec.defaultBranch`
2. Если конфигурации нет, получи удалённый репозиторий из явной настройки или
   единственного доступного удалённого репозитория и прочитай
   `refs/remotes/{remote}/HEAD` через `git symbolic-ref`
3. Если источник неоднозначен или удалённый `HEAD` отсутствует, запроси точное
   имя ветки у пользователя

Не используй upstream текущей ветки: он может указывать на рабочую ветку. Не
предполагай имя основной ветки.

## Проверка Git

До команд OpenSpec выполни все проверки:

1. Текущая ветка из `git branch --show-current` точно совпадает с основной веткой
2. `git status --porcelain` подтверждает чистую рабочую копию
3. Из `state.md` и отчётов получен точный `{CHANGE_HEAD}`, относящийся к
   реализации изменения
4. `git merge-base --is-ancestor {CHANGE_HEAD} HEAD` подтверждает достижимость
   результата изменения из текущей основной ветки

Передай эти данные событием `archive-guard` в
[исполняемый интерфейс разработки](../openspec-development/scripts/openspec-orchestrate).
Продолжай только при решении `archive-ready`.

Отсутствующий `{CHANGE_HEAD}`, другая ветка, грязная рабочая копия или
недостижимый результат блокируют архивирование. Во время архивации не переключай ветки,
не сливай и не создавай коммит.

## Выбор изменения

Прочитай полный JSON `openspec list --json`:

* 0 активных изменений — остановись
* 1 активное изменение — используй его только после сверки с явным запросом
* N активных изменений — пользователь выбирает одно; не выбирай автоматически

Затем прочитай полные JSON `openspec status <id> --json` и
`openspec instructions apply <id> --json`. Покажи незавершённые пункты; они
блокируют архивирование и не заменяются подтверждением пользователя.

## Архивирование

После всех проверок выполни штатный
`openspec archive <id> --yes --json`. Не используй флаги, пропускающие
спецификации или валидацию. После успешного ответа не выполняй Git-операции.

## Ошибки формы

Если архивирование вернуло ошибку формы, продолжи прежнего планировщика. Он
меняет только артефакты активного изменения и повторно валидирует их.

Проверь влияние исправления на требования, задачи и реализацию. Если влияния
нет, передай событие `archive-impact` с отрицательным результатом и повтори
предварительные проверки. Если влияние на реализацию есть, передай положительный
результат: интерфейс вернёт процесс в разработку. Передай обновлённые артефакты
исполнителю и не повторяй архивирование в этом цикле.
