# Исполнение планов

Исполняй план по проверяемым рабочим блокам. Выбирай простейшую схему
координации, которая сокращает критический путь и сохраняет качество.

## Подготовка

1. Прочитай план и правила репозитория.
2. Найди неоднозначности, отсутствующие зависимости и обязательные
   пользовательские подтверждения.
3. Сгруппируй пункты в минимальные отдельно принимаемые рабочие блоки.
4. Зафиксируй зависимости, проверяемый результат, риск и тесты каждого блока.

Если план противоречив или требует значимого архитектурного выбора, задай один
пакетный вопрос до реализации.

## Выбор способа исполнения

Один связный блок выполняй локально. Если он велик, но имеет ясную границу,
допустим один исполнитель с одним рабочим ходом; отдельный агент не является
обязательным.

Два и более независимых блока передавай
`subagent-driven-development`, только если:

* каждый блок можно принять или отклонить независимо;
* параллельность или свежий контекст окупают координацию;
* заранее записаны бюджет ходов, бюджет моделей и бюджет координации;
* исполнители работают в изолированных областях либо только читают один
  неизменяемый снимок.

Последовательные пункты, меняющие один артефакт, остаются у одного исполнителя.
Не дроби отдельно создание, наполнение, полировку и синхронизацию одного
результата.

## Бюджет

До первого запуска запиши:

```text
agent-turn budget:
  implementation = {число ходов}
  review = {число ходов}
  repair = {число ходов}
  nested = {число заранее спроектированных дочерних ходов}
  total = {сумма}

coordination budget:
  followups = {число}
  status checks = {число}
  unsolicited messages = 0
```

Нулевой `nested` означает, что вложенная делегация не запланирована для этого
исполнения. Ненулевой бюджет допустим для двух и более независимых подблоков,
если корневой координатор заранее определил их границы и право родителя на
запуск.

Выбирай экономичный профиль для механической работы, стандартный для
многофайловой реализации и отладки, самый сильный для архитектуры, безопасности
и итогового ревью. `max` и `ultra` требуют записанного обоснования для
конкретной роли.

## Исполнение

Для каждого блока:

1. Зафиксируй исходный `HEAD` и границу блока.
2. Реализуй только требования блока.
3. Запускай узкие проверки во время работы и один уместный полный набор перед
   фиксацией результата.
4. Проверь diff на полноту, лишний объём и качество тестов.
5. Зафиксируй результат и обнови состояние плана.

Не дублируй работу активного исполнителя. Не запускай ревью движущейся цели.
Обычный контур — реализация, одно ревью по риску, один пакет исправлений и
узкая перепроверка.

## Контрольные точки

Показывай пользователю результат, если следующий шаг дорог, субъективен,
необратим или требует внешнего решения. В остальных случаях продолжай до
следующей содержательной контрольной точки.

После завершения всех блоков выполни итоговую проверку требований и свежую
верификацию. Затем используй принятый в репозитории процесс завершения ветки.

## Остановка

Остановись и сообщи пользователю, если:

* отсутствует обязательное решение или разрешение;
* план нельзя исполнить без значимого расширения области;
* исчерпан согласованный бюджет агентов;
* после допустимого цикла остаётся блокирующее замечание.

Не начинай новый координационный контур ради неблокирующей полировки.
