# Полное транскрибирование

## Получить аудио и субтитры

Для URL сначала проверить доступ и дорожки через `yt-dlp --list-subs --skip-download`. Если источник требует другой доступный инструмент, использовать его без обхода ограничений доступа. Если полную запись получить не удалось, сообщить границы доступного материала.

Создать отдельный временный каталог, например через `mktemp -d`, и сохранить его путь в переменную `TRANSCRIBE_TMP`. Ручные и автоматические дорожки скачивать раздельно, чтобы одинаковый язык не приводил к потере одной из них:

```bash
yt-dlp --write-subs --no-write-auto-subs --sub-langs "$SOURCE_LANGS" \
  --sub-format 'json3/vtt/srt/best' --skip-download \
  -o "$TRANSCRIBE_TMP/manual/source" "$VIDEO_URL"
yt-dlp --write-auto-subs --no-write-subs --sub-langs "$SOURCE_LANGS" \
  --sub-format 'json3/vtt/srt/best' --skip-download \
  -o "$TRANSCRIBE_TMP/automatic/source" "$VIDEO_URL"
yt-dlp -x --audio-format wav -o "$TRANSCRIBE_TMP/audio.%(ext)s" "$VIDEO_URL"
```

Перед запуском задать `VIDEO_URL` и `SOURCE_LANGS` по фактическому источнику. Получить все подходящие ручные и автоматические дорожки на языках речи. Переводные дорожки можно использовать как контекст, но не считать независимым подтверждением оригинальной формулировки. Если дорожек нет, продолжить с двумя ASR.

Проверить аудиодорожки и длительность через `ffprobe`. Для локального видео или полученного аудио подготовить несжатый mono PCM 16 kHz, сохранив оригинал:

```bash
ffmpeg -n -i "$MEDIA_PATH" -map "$AUDIO_STREAM" -vn -ac 1 -ar 16000 \
  -c:a pcm_s16le "$TRANSCRIBE_TMP/asr.wav"
```

`MEDIA_PATH` — фактический путь, `AUDIO_STREAM` — выбранная по метаданным дорожка, например `0:a:0`. При разделённых голосах на разных дорожках сначала обеспечить сохранение всех говорящих. Не выбирать дорожку молча, если это может потерять участника. Сопоставить длительности исходника и извлечённого аудио.

Нормализовать субтитры, сохраняя интервалы, участников и происхождение дорожки. Удалять служебные события и накопительные дубли автосубтитров, а не повторы речи. Проверить временное смещение по характерным фразам в начале, середине и конце. Если смещение меняется, проверить монтаж и дрейф, не применять один сдвиг ко всему файлу.

## Подготовить словарь

Из доступных документов, слайдов и страниц выписать в `$TRANSCRIBE_TMP/terms.txt` имена, продукты, технологии, аббревиатуры, формулы и короткие заголовки. Словарь не содержит предложений и тезисов для вставки в речь. Учитывать происхождение и неоднозначные написания. Для уточнения термина можно прочитать нужную страницу или посмотреть отдельный кадр. Это не требует поиска смен слайдов или привязки всей записи к презентации.

## Выполнить два независимых распознавания

**Whisper:** использовать мультиязычную `large-v3` на подходящем локальном движке. Другую модель Whisper выбирать только при подтверждённом качестве не ниже и соответствии языкам записи. Сохранять полные сегменты, таймкоды слов при поддержке и доступные показатели уверенности. Записать версии движка и модели. Не переводить речь, не исключать иноязычные фрагменты жёстким языковым ограничением.

**Parakeet:** на Apple Silicon использовать подготовленный пакет FluidAudio `v0.15.5` с Parakeet TDT v3. Сначала проверить путь пакета, версию, локальные модели и параметры `fluidaudiocli transcribe --help`. Пример запуска из подготовленного пакета, с фактическим кодом языка в `LANGUAGE_CODE`:

```bash
swift run --package-path "$FLUIDAUDIO_PACKAGE" -c release fluidaudiocli \
  transcribe "$TRANSCRIBE_TMP/asr.wav" \
  --language "$LANGUAGE_CODE" \
  --word-timestamps \
  --output-json "$TRANSCRIBE_TMP/parakeet.json" \
  --custom-vocab "$TRANSCRIBE_TMP/terms.txt"
```

Проверить наличие `wordTimings` и полное покрытие речи. Не использовать внутренний HTTP API FluidVoice. Если FluidAudio несовместим со средой, использовать локальный `sherpa-onnx` с Parakeet TDT v3 и сохранить эквивалентные таймкоды. Если модель не поддерживает язык записи или второго ASR получить не удалось, запросить решение пользователя. Не снижать требования молча.

Не передавать результат одного ASR другому. Оба обрабатывают всю запись. При разбиении сохранять исходные смещения, перекрытие для проверки стыков и признак завершения каждого фрагмента. Проверять, что работа действительно завершилась, а не судить об этом по наличию выходного файла. Не запускать две большие модели одновременно, если памяти для этого недостаточно.

## Сверить источники

1. Привести все интервалы к секундам от начала исходной записи.
2. Сопоставить короткие фрагменты Whisper, Parakeet и субтитров по времени и тексту. Отдельно отметить речь, найденную только одним источником, пустые интервалы, повторы и пересечения говорящих.
3. Выделить расхождения в словах, именах, числах, отрицаниях, условиях, причинности и степени уверенности. Разница только в пунктуации не требует прослушивания. Показатели уверенности разных движков не сравнивать как одну шкалу, учитывать доступные сигналы каждого отдельно.
4. Фактически переслушать существенные расхождения и участки низкой уверенности с контекстом до и после. Только затем выбирать написание по материалам среди фонетически правдоподобных вариантов.
5. При оставшемся сомнении использовать `[неразборчиво, 00:12:34]` либо `[вероятно: SourceCraft]`. Если прослушивание недоступно, сохранить отметки и сообщить о незавершённой проверке.

Совпадение всех текстовых источников не закрывает уже обнаруженное сомнение. Это правило относится к спорным местам. Не помечать весь согласующийся текст как вероятный только потому, что он не переслушан целиком.

## Отредактировать речь

- Сохранить хронологию, все мысли, примеры, шутки, эмоциональные акценты, вопросы и ответы. Удалять запинки, слова-паразиты, ложные старты и механические повторы только без потери смысла или выразительности.
- Исправлять пунктуацию и однозначные ошибки распознавания. Не исправлять фактические ошибки лектора по памяти. Значимую самокоррекцию, отрицание и ограничение сохранять, даже если фраза станет менее гладкой.
- Не заменять ясную формулировку синонимом со слайда, не переводить речь и не превращать расшифровку в конспект.
- Сохранять подтверждённые метки участников из источников. Для неизвестных людей использовать стабильные `Спикер 1`, `Спикер 2`. Роль `Участник` использовать, когда она известна. Имена не выводить из внешности или голоса. Если несколько голосов нельзя надёжно разметить, использовать доступную локальную диаризацию или явно отметить неопределённую атрибуцию.
- Начинать разделы и самостоятельные реплики таймкодом. Для веб-видео делать ссылку на момент только при поддержке источником и после проверки формата. Для локального файла использовать `[ЧЧ:ММ:СС]`.

## Принять транскрипт

Проверить всю речь от первой до последней реплики, включая вопросы и стыки фрагментов. Сопоставить сырой и очищенный текст: числа, отрицания, условия, примеры, вопросы, участники и степень уверенности не потеряны и не добавлены. Проверить единообразие терминов и корректность ссылок. Для сомнительных мест сохранить решения и таймкоды в [пакете источников](source-bundle.md), если он нужен.

Файл транскрипта содержит чистовую речь. Ограничения проверки сообщать отдельно.
