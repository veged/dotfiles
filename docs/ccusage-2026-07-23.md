# ccusage: Claude Code и Codex за 21–23 июля 2026

Актуально на 2026-07-23 для `ccusage` 20.0.18. Версия зафиксирована по
[package metadata репозитория](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/apps/ccusage/package.json)
и [npm](https://www.npmjs.com/package/ccusage).

## Команды

Диапазон включает обе границы. Часовой пояс указан явно, чтобы «календарный
день» означал день по Москве, а не зависел от окружения:

```bash
npx --yes ccusage@20.0.18 claude daily \
  --since 20260721 \
  --until 20260723 \
  --timezone Europe/Moscow \
  --json

npx --yes ccusage@20.0.18 codex daily \
  --since 20260721 \
  --until 20260723 \
  --timezone Europe/Moscow \
  --speed auto \
  --json
```

Для Claude фильтры документированы в формате `YYYYMMDD`; Codex принимает также
`YYYY-MM-DD`, а `--until` у него явно включителен. Опции подтверждаются
[схемой CLI](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage-cli/src/cli-help.json)
и [snapshot справки `codex daily`](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage-cli/src/snapshots/ccusage_cli__tests__codex_daily_help.snap).
Фильтр применяется к дате каждого usage-события после перевода timestamp в
указанный часовой пояс. Поэтому сессия, пересекающая полночь, делится между
днями, а не целиком относится к дате начала
([реализация фильтра](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/summary.rs#L270-L282)).
Раздельные команды предпочтительнее `ccusage daily`: объединённая команда
добавляет все обнаруженные источники, а не только Claude и Codex
([документация daily](https://ccusage.com/guide/daily-reports)).

## Поддержка источников

- Claude Code читается из `~/.config/claude/projects/` и
  `~/.claude/projects/`; `CLAUDE_CONFIG_DIR` может содержать несколько путей
  через запятую. Повторённые sidechain-сообщения дедуплицируются, повреждённые
  строки JSONL пропускаются
  ([описание адаптера](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/claude/README.md)).
- Поддержка Codex помечена как экспериментальная. Адаптер читает
  `sessions/` и `archived_sessions/` под `CODEX_HOME` (по умолчанию
  `~/.codex`), поддерживает несколько корней через запятую и сохранённый
  `codex exec --json`. Совпадающий активный файл имеет приоритет над архивным
  ([официальная документация](https://ccusage.com/guide/codex/),
  [реализация путей](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/codex/paths.rs)).
- Codex агрегирует `token_count`: использует `last_token_usage`, а при наличии
  только накопительного `total_token_usage` вычисляет дельту. Reasoning-токены
  уже входят в output-биллинг и не должны прибавляться к стоимости повторно
  ([описание адаптера](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/codex/README.md),
  [парсер](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/codex/parser.rs)).

## JSON-контракт

Claude daily:

```text
{
  daily: [{
    date,
    inputTokens, outputTokens,
    cacheCreationTokens, cacheReadTokens,
    totalTokens, totalCost,
    modelsUsed,
    modelBreakdowns: [{
      modelName,
      inputTokens, outputTokens,
      cacheCreationTokens, cacheReadTokens,
      cost
    }]
  }],
  totals: {
    inputTokens, outputTokens,
    cacheCreationTokens, cacheReadTokens,
    totalTokens, totalCost
  }
}
```

Точная сериализация находится в
[команде Claude daily](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/commands/mod.rs#L31-L55)
и [snapshot строки отчёта](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/snapshots/ccusage__output__tests__snapshots_summary_json_with_optional_fields_and_model_breakdowns.snap).

Codex daily:

```text
{
  daily: [{
    date,
    inputTokens,
    cacheCreationTokens,
    cacheReadTokens,
    outputTokens,
    reasoningOutputTokens,
    totalTokens,
    costUSD,
    models: {
      "<model>": {
        inputTokens,
        cacheCreationTokens,
        cacheReadTokens,
        outputTokens,
        reasoningOutputTokens,
        totalTokens,
        isFallback
      }
    }
  }],
  totals: {
    inputTokens,
    cacheCreationTokens,
    cacheReadTokens,
    outputTokens,
    reasoningOutputTokens,
    totalTokens,
    costUSD
  }
}
```

У Codex `inputTokens` в отчёте — input без cached input,
`cacheCreationTokens` сейчас всегда `0`, а `reasoningOutputTokens` —
информационная детализация output. Не следует восстанавливать `totalTokens`
простым сложением всех видимых полей. Контракт подтверждается
[генератором отчёта](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/codex/report.rs)
и [JSON snapshot](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/codex/snapshots/ccusage__adapter__codex__tests__snapshots_codex_reports_for_periods_sessions_costs_and_fallback_models.snap).

Важно: у Claude стоимость называется `totalCost`/`cost`, у Codex —
`costUSD`. Примеры на сайте местами показывают старую унифицированную форму;
для автоматизации выше использован контракт текущего исходного кода 20.0.18.

## Стоимость и ограничения

- Claude по умолчанию использует `--mode auto`: берёт записанный `costUSD`,
  если он есть, иначе рассчитывает стоимость по токенам. `calculate` всегда
  пересчитывает по ценам модели, `display` показывает только записанную
  стоимость и даёт ноль при её отсутствии
  ([документация режимов](https://ccusage.com/guide/cost-modes/),
  [реализация](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/cost.rs)).
- Codex не имеет `--mode`: стоимость всегда рассчитывается по токенам и
  ценам модели. Отсутствующая цена даёт `0` для этой модели и предупреждение,
  то есть итог исключает её стоимость
  ([расчёт Codex](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/codex/report.rs)).
- Без `--offline` ccusage обновляет цены из LiteLLM; `--offline` использует
  встроенный snapshot. Поэтому пересчитанная историческая стоимость — оценка
  по доступной базе цен, а не подтверждение фактического списания.
- Codex-логи обычно не фиксируют speed tier. `--speed auto` смотрит текущий
  `config.toml` каждого `CODEX_HOME`: `service_tier = "priority"` или
  `"fast"` переводит весь расчёт в fast. При нескольких корнях достаточно
  одного fast-конфига. Если текущий конфиг не отражает режим за исследуемые
  дни, точнее явно указать `--speed standard` или `--speed fast`
  ([реализация определения](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/codex/speed.rs)).
- При отсутствии модели текущий парсер подставляет `gpt-5` и ставит
  `isFallback: true`; такие строки приблизительны. Это расходится с
  troubleshooting на сайте, где ещё сказано, что часть старых событий
  пропускается. Для 20.0.18 следует ориентироваться на
  [реализацию fallback](https://github.com/ccusage/ccusage/blob/31e084afbca3981af97ab6b55abe4f38f451bad4/rust/crates/ccusage/src/adapter/codex/parser.rs#L487-L530),
  сохраняя это расхождение как риск.
